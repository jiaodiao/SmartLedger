# 定制版更新

功能定制及上游合并保留清单统一维护在 [用户定制功能与合并参考](customizations.md)。构建发布前先核对该清单；用户当前安排由 Grok Bot 构建发布，本地只修改并推送源码，不另外交付测试安装包。

更新来源：`jiaodiao/SmartLedger` 的最新正式 GitHub Release。
首次接入版本：`1.0.28.1`，`versionCode = 30`，对应上游 `1.0.28`。

## 首次安装

旧定制版仍查询作者仓库，因此首次必须手动下载安装本仓库发布的 APK，并直接覆盖安装。不要卸载旧版。
安装后可在设置中点击检查更新。首页启动时也会检查，成功检查后 30 分钟内不重复请求；下载后需要用户在 Android 安装界面确认。

## 后续发布

1. 合并需要的源码更新，检查数据库结构变化及迁移，验证定制功能。
2. 修改 `app/build.gradle.kts` 的版本。显示版本使用“上游版本.定制修订号”，例如 `1.0.28.2`；内部 `versionCode` 每次发布递增，不能被上游值覆盖回退。
3. 沿用首次定制 APK 的签名打包。目前交付包使用本地 `debug.keystore`，不要重新生成密钥或改用另一把 release 密钥。云构建也必须使用相同密钥。
4. 核对 APK 包名、版本与签名，发布正式（非草稿、非预发布）GitHub Release，例如标签 `v1.0.28.2`，将它设为最新版本，并只附带一个供手机更新的 APK。
5. 手机检查更新，下载后覆盖安装。

仅推送源码不会发布手机更新；APK 必须成为 Release 附件。不要将签名私钥、密码或访问令牌提交到仓库。
